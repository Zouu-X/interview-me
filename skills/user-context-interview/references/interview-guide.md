# Adaptive interview guide

Read this when selecting follow-ups, handling an unhelpful answer, or refreshing context. Choose only the questions that could change future help. Do not administer this as a questionnaire.

## Pick questions by consequence

Before asking, identify the decision the answer will affect. If the agent would behave the same either way, skip the question. Ask about the user's actual work before requesting broad life history.

| Signal | Useful follow-up | Consequence to capture |
| --- | --- | --- |
| “Help me with everything.” | “What took the most avoidable effort this week?” | A concrete starting use case |
| “I want to get better at X.” | “What would progress look like in a month?” | An outcome and relevant horizon |
| “I know the basics.” | “Which parts can I assume, and where do examples help?” | Explanation starting point, not a fixed ability label |
| “Keep it short.” | “For a difficult decision, would a recommendation and two reasons be enough?” | A usable default with room for exceptions |
| “Don't keep asking permission.” | “Which reversible work should I handle on my own, and which decisions need you?” | Boundaries within the host's authorization rules |
| “Push back on me.” | “Can you give an example of the kind of disagreement you want?” | Evidence-focused challenge and preferred tone |
| “You keep missing what I mean.” | “Can we look at one recent example and what you wanted instead?” | A specific behavior to change |
| “I don't know.” | Offer two concrete examples, or move on. | Unresolved preference; do not invent an answer |
| “I only have two minutes.” | Ask for the main goal and the single most useful change in agent behavior. | A useful partial profile |

## Practical opening patterns

- **First interview, no context:** ask about the most important upcoming use and what good help looks like.
- **Existing context:** “I understand you're working on X and prefer Y. What has changed, or what do I keep misunderstanding?” Use only relevant accessible facts.
- **Task-limited request:** stay within that task or area; do not expand to family, health, finances, or personal history.
- **User prefers choices:** offer meaningful alternatives and a free-text route. Do not add an invented “Other” option if the host already provides one.
- **No interactive tool:** ask the same question in ordinary text. No apology or tool installation is needed.

## Learn through examples

Prefer “What should I have done differently in that answer?” to “What is your personality?” Ask for examples the user is comfortable sharing; do not require private messages or confidential documents.

Separate the reason from the actionable preference:

- Answer: “Long lists overwhelm me when I am planning my week.”
- Useful profile: “For weekly planning, start with the top three actions and expand on request.”
- Avoid: “The user cannot handle complex information.”

When preferences depend on context, keep the condition:

- “Use Chinese for day-to-day discussion and English for application materials.”
- “Proceed independently with reversible edits; ask before publishing.”
- “Explain unfamiliar concepts step by step, but keep routine status updates short.”

Ask about these distinctions only if the conversation suggests them. They are examples, not defaults for every user.

## Review without adding friction

Reflect useful discoveries briefly throughout the conversation. At the end, show a compact summary, not an exhaustive transcript. Do not require confirmation after every answer. If the user already requested saving, persist the authorized material and give a receipt; if they have not, offer retention after they can see what would be kept.

Do not silently harden an inference into a fact. For example, a request for a detailed explanation once does not establish that the user always prefers detail. Ask if it is a general preference, retain it as scoped to that task, or omit it.

## Refresh strategy

1. Read only the relevant existing profile or memory.
2. Identify likely change points: completed milestones, current projects, explicit corrections, and conflicts. A long time since confirmation is not enough to overwrite a fact.
3. Ask one focused question about the highest-impact change.
4. Update confirmed differences and their practical consequences. Keep stable items and unrelated text.
5. Report changed categories and storage status; do not expose removed sensitive values.

Example: if an entry says the user was seeking internships last year, ask what they are pursuing now before replacing it with an assumed job or new goal.

## Natural stopping points

End when the agent can identify the main purpose, a few working preferences, and important boundaries, or whenever the user wants to stop. A useful profile can have two entries. Offer deeper exploration only when a concrete gap remains and the user has time.
